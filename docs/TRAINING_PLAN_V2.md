# 训练与性能优化方案 v2（2026-11-25）

> 上一轮（`TELEMETRY_V3_2026-11-25.md`）只解决了"模型准不准"：弯时占比 MAE 降 61%，
> 但端到端收益没提升，las_vegas 还出现回退。本方案把目标从"回归更准"改成
> **"建议更优 + 系统更快 + 每一步可验收"**，并记录本轮已执行的部分。

---

## 0. 现状诊断（不是猜的）

| 事实 | 证据 | 含义 |
|---|---|---|
| 精度提升没换来收益 | 42 组 A/B：8 胜 / 7 负 / 27 平，均值 −140.6 → −135.1 ms | 瓶颈不在回归精度 |
| 重要度几乎没变 | 19 个共有站逐弯重要度平均 L1 差 0.004 | 优化器输入几乎一样，输出自然一样 |
| 对步长是刀尖响应 | authored 信任系数扫描：1.0/0.8 → +5.9 ms，0.6 → −138 ms，0.4 → +81 ms，0.3 → +308 ms | 最优点附近平台极窄，调系数=过拟合 |
| 个别站建议劣于默认 | spielberg 干 +144.5 / 湿 +524.9 ms，spa 干 +41.8 ms（两版模型完全一致） | 与模型无关，是锚点/目标函数问题 |
| 单次建议 104.1 ms | 42 组 A/B 实测（优化前） | 有明确优化空间 |

**结论：下一阶段的投入顺序是「稳定性 > 端到端收益 > 回归精度」。**

## 2. 数据契约与质检门禁

### 2.1 数据源与职责

| 源 | 内容 | 规模（2026-11-25） | 门禁 |
|---|---|---|---|
| 官方计时 FastF1 | Race 全量逐点 → 干净圈 → 逐弯 | 19,459 圈 / 314,891 样本 / 21 站 | 见 2.3 |
| OpenF1 | 圈级 sector / stint / 进站 | 24,615 圈 / 1,324 stint / 21 站 | 与官方圈速交叉核对 |
| f1laps 调教 | 游戏口径 20 项调教 + 圈速 | 899 条 / 24 站 | 独立任务，不与真实圈速配对 |

**边界（写死，不再重复讨论）**：游戏内 UDP 遥测只能本机采集，无法爬取；
公开真实遥测不含车队调教，因此「同圈既有真实遥测又有真实调教」的数据不存在。

### 2.2 字段口径（训练前强制）

1. `max_lateral_g` / `max_long_g` 是**原始加速度**：÷9.81，按 6 g 截尾；`max_long_g==0` 视为缺失。
2. `tyre_life` 的字符串 `"None"` → 缺失。
3. `drs_pct` 恒为 0 → 剔除。
4. 逐弯样本必须 join 圈级 `tyre_life / stint / fresh_tyre`（当前 311,001/314,891 有值）。
5. 湿圈 506 圈中 452 圈来自圣保罗 → **不建湿滑主模型**，湿圈权重 0.5 且单独报告。

### 2.3 清洗口径（干净圈）

排除：第 1 圈、`status != "1"`（非绿旗）、进站/出站圈（`pin/pout`）、赛会删除（`del`）、
计时不准（`iacc=false`）、FastF1 补造（`ff1G=true`）。

### 2.4 交叉核对（OpenF1 vs 官方）

每次重建数据后跑一次：同 (赛道, 车手, 圈) 的 `lap_duration` 与官方 `lap_time_s`
中位绝对偏差 **≤0.05%**；超过则在报告中标注该站不可用于训练。
本轮 21 站全部通过抽样核对（详见 `data/f1_2026/openf1_manifest.json`）。

## 3. 切分矩阵（三套都要报）

| 切分 | 做法 | 回答的问题 | 上线依据 |
|---|---|---|---|
| 分站留出 | `splits.json` 15/3/3 | 能不能用于新赛道 | ✅ 主依据 |
| 车手留出 | 25 人留 5 人 | 能不能用于新车手 | ✅ 辅助 |
| 时间留出 | 前 15 站训练、后 6 站测试 | 最接近真实上线 | ✅ 辅助 |

禁随机按圈报成绩：同场同弯泄漏会给出 R²≈0.97 的假成绩（现役产物就是这么来的）。

## 4. 模型阶梯（每级必须打败上一级才升级）

| 级 | 形态 | 现状 | 升级条件 |
|---|---|---|---|
| L0 | (赛道×弯号) 中位数 + 经验贝叶斯收缩（k=20） | 同类 MAE 0.002808 | 基线，永久保留 |
| L1 | L0 + 14 项工况残差岭（α=3） | **已上线 candidate**，MAE 0.002836 | 分站留出不退、端到端不退 |
| L2 | L1 + 轮胎/进站上下文 | 实测**零增益**（0.002836 → 0.002836） | 暂不投入，除非新数据改变结论 |
| L3 | 端到端可微优化 | 未开始 | 不做（样本量与可解释性都不支持） |

引擎兼容：`telemetry_surrogate.json` 新增 `corner_baseline` 块；
无该块时 `surrogate.py` 走旧路径（已验：旧产物 333 条测试全绿）。

## 5. 端到端验收（唯一算数的环节）

**方法**：21 站 ×（干/湿）= 42 组，输入同一份模拟遥测摘要（路肩冲击 2.2/1.7、刮底 1.3、
四轮温度/胎压/磨损、刹车温度、软胎），默认调教出发，走真实
`generate_suggestion(model_type="hybrid")`；建议后的调教用**独立物理仿真**
`simulate_lap_delta_ms` 打分（正 = 比默认更慢）。

**硬门槛**：
1. 平均物理收益 ≤ −150 ms；
2. `sim_delta_ms > 0` 的组数 = 0；
3. 单次调用 P50 ≤ 50 ms；
4. 42 组 0 异常。

**纪律**：
- 换模型前必须 `reset_surrogate()`（逐弯评价按赛道缓存，不清会串场，本轮已踩过）；
- 两版模型必须同输入、同参数、同进程外分别跑；
- 报告同时给均值与中位数，禁止只报中位数好看的那一个。

## 6. 发布与回滚

```
train → candidate → 分站留出 + 端到端 A/B → 人工看报告 → promote（workflow 勾选）
                                          ↘ 不达标：只留 candidate + eval_rejected
```

- 生产模型路径：`setup_tuner/resources/models/telemetry_surrogate.json`
- 候选路径：`setup_tuner/resources/models/candidates/`
- 回滚：保留上一版文件即可；引擎对缺失 `corner_baseline` 自动降级，不需要改代码。
- 每次 promote 必须附：数据版本、切分、三项指标、A/B 结果、回滚点。

## 8. 本轮已执行（系统性能）

| 改动 | 位置 | 效果 |
|---|---|---|
| 逐弯评价按 (赛道, 反馈弯集合) 缓存 | `lap_model.corner_evaluations` | 去掉每轮重建 24 项的开销 |
| 坐标上升对 delta 记忆化 | `sim_optimizer.sim_refine` | 41 次前向 → 仅接受步才重算 |
| MLP 前向 `sum(map(mul, …))` + 内联 ReLU | `pure_nn._forward` | 加法顺序不变，结果逐位相同 |
| 单调性守卫 | `sim_optimizer` 收尾 | 精修后更慢则退回初始改动，不再返回"越优化越慢"的解 |

**实测**：42 组 A/B 的单次建议 104.1/104.9 ms → **61.0/62.2 ms（−41%）**，
单赛道重复调用 32–36 ms（Monza 35.5 ms、Spielberg 32.4 ms）；
42 组物理收益与优化前完全一致（−140.6 / −135.1 ms），确认无行为漂移。
测试：`pytest -q` 全量通过。

**本轮试过但否决的方案**：按锚点可信度收缩 authored 赛道改动幅度（trust=0.6）。
在 las_vegas/sao_paulo 上收益看似从 +5.9/−29.6 变成 −138.0/−146.5 ms，
但 0.8/0.6/0.4/0.3 扫描结果不单调，属于对步长过拟合，已回退并写进注释。

## 9. 下一轮 P0（按顺序）

1. **spielberg / spa 建议劣于默认**：两版模型一致 → 查锚点与目标函数的阻力/下压力项，
   先修"建议比默认更慢"这一类硬伤。
2. **优化器步长稳定性**：刀尖响应说明目标函数曲率异常；先做步长/预算的敏感性分析，
   再决定是否改算法（不要在单站上挑系数）。
3. **P95 延迟**：当前只测了均值，补分位与冷启动（首次加载模型）数据。
4. 车手留出与时间留出补齐后再允许 promote 新模型。
