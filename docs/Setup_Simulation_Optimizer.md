# 神经网络模拟优化（Setup Simulation Optimizer）

> 2026-09-19 大改：把「参数矩阵给方向，神经网络不断模拟优化」真正接进调教建议主链路。
> 零第三方依赖（**不需要 PyTorch**），模型与训练数据全部可复算。

## 1. 为什么要有这一层

旧实现的三处硬伤（用户实测反馈）：

| 症状 | 根因 |
|------|------|
| UI 提示"缺 PyTorch/权重，已按规则引擎生成" | 神经网络分支依赖 PyTorch，venv 未安装；权重文件也不存在 → `available=False` 静默降级 |
| "没有利用遥测数据训练模型" | 旧训练脚本用**规则引擎自己**生成标签，学到的只是规则矩阵的复制品 |
| "还是显示混合、神经网络" | 旧实现是"规则 60% + 网络 40%"的一次性加权，**没有模拟迭代** |

## 2. 三段式架构

```
① 参数矩阵给方向                       ② 神经网络不断模拟优化                ③ 报告
─────────────────────                ─────────────────────────          ─────────────
Dx (9 维需求)
  × C (9×20 耦合矩阵)
  → 遥测/赛道/风格增益
  → 圈级优化（残差+代价坐标上升）
  → 整体性收口（配平/预算）
  = delta0  ─────────────────────────► sim_refine(delta0)
                                        逐参数试步（固定顺序/固定步长）
                                        NN 预测候选调教圈速
                                        更优且"付得起"→ 接受，迭代
                                        = final_delta ───────────────► holistic.simulation
                                                                        {model, iterations,
                                                                         accepted, gain_ms,
                                                                         trace[]}
```

实现位置：

| 环节 | 文件 |
|------|------|
| 模型（加载/特征/推理，纯标准库） | `setup_tuner/engine/setup_sim.py` |
| 模拟优化循环（坐标上升 + 守门） | `setup_tuner/engine/sim_optimizer.py` |
| 管线接线与报告 | `setup_tuner/engine/engine.py::generate_suggestion` |
| 数据构建（遥测锚定仿真） | `scripts/build_setup_sim_dataset.py` |

| 验收（遥测 + 真值复核） | `scripts/verify_optimization_telemetry.py` |

## 3. 训练数据：遥测锚定的准稳态仿真

公开世界**不存在**「每个调教组合 → 圈速」的监督数据：外部 2026 真遥测没有调教信息，
本地游戏录制只有 14 圈。因此采用工程界通行的**遥测锚定 + 文档化物理**路线。

**锚点（全部来自真实遥测，80,983 条 2026 逐弯样本）**

- 每赛道 × 每弯：入弯/弯心/出弯速度、弯时、刹车占比（取中位数）
- 每赛道：中位圈速、直道时间占比（重刹指数 + 气动依赖 + 快弯占比 的组合估计）、
  抓地/气动/制动需求指数、均速（赛道长度 ÷ 中位圈速）

**结构（车辆动力学，非拟合参数）**

- `v ∝ √a_grip`：抓地提升 1% → 弯速提升 0.5%（相位分解：入弯/弯心/出弯）
- `Δt ≈ -t_corner · Δv/v`：弯速提升 → 弯时下降
- 气动抓地按弯型加权：慢弯 0.08 / 中速弯 0.30 / 快弯 0.65（气动载荷 ∝ v²）
- **诱导阻力 ∝ 下压力²**：这是"内点最优"的来源 —— 没有它，最优解永远落在翼角极值上
- 双侧罚：胎压离开工作窗口、刹车平衡偏离默认 → 抓地/制动效能下降（非线性的来源）
- 离地间隙过低 → 刮底罚

**灵敏度系数口径（诚实声明）**

`EFFECTS` 表中全部是**本项目标定的相对权重**，不是官方数值，也不宣称绝对精度：
- 方向（符号）来自 F1 车辆动力学共识与公开调教指南；
- 幅度标定到公开工程量级范围（前后翼 ±10 档 ≈ 0.2–0.5 s/圈；外倾 ±0.5° ≈ 0.1 s/圈；
  悬挂软硬整档 ≈ 0.05–0.15 s/圈），并由 `--calibrate-only` 打印标定表人工复核；
- 阻力系数由「逐赛道最优翼角」目标标定：monaco +12 档（最想加翼）、spa −6 档
  （最想减翼），与 F1 调教共识一致。

产物：`data/training/setup_sim_dataset.jsonl`（18,200 行 = 13 赛道 × 1400 组调教）。

## 4. 模型：纯标准库 MLP

- 输入 42 维：赛道 one-hot(13) + 赛道聚合特征(5) + 调教 20 + 工况(4)
- 结构 `[42, 48, 24, 1]`，ReLU + Adam 反传，全部标准库实现（`engine/pure_nn.py`）
- 输出缩放：目标按训练集均值/标准差归一到 ~1 量级再训练，推理乘回（条件数改善）
- 落盘：`data/models/setup_sim_nn.json`（权重 + 每赛道特征表 + 指标 + 缩放口径）

**验证集指标**：MAE **53.3 ms** / R² **0.9959**（零改动基线 MAE 2758 ms）。

**优化器实际用到的量是"相邻候选的差异"，单独测过**：

| 口径 | 平均 | 中位 | p90 | 方向正确率 |
|------|------|------|-----|-----------|
| 相邻候选差异误差 | 29.0 ms | 15.0 ms | 75.4 ms | **90%**（>30ms 显著移动 **95%**） |

接受阈值据此定为 20 ms（落在模型可靠区间内，避免追逐噪声）。

## 5. 模拟优化循环（`sim_refine`）

```
输入: delta0（矩阵方向的结果）、current_setup、track_id、dx
输出: 精修后的 delta、迭代轨迹、模拟前后圈速

每轮（≤3 轮）:
  按固定顺序遍历可优化参数:
    尝试 ± 一个网格步（0.25 × max_delta，对齐 step 档位）
    约束：|总改动| ≤ max_delta 且 current+delta ∈ [min, max]；左右胎压保持一致
    用 NN 预测候选调教 → 模拟圈速增量
    接受条件（同时满足）:
      a) 模拟提升 ≥ 20 ms
      b) 模拟提升 ≥ 5.0 × 手写目标代价增量     ← "付得起"原则
         且整轮代价预算 ≤ 0.08
```

- **确定性**：无随机、无时间依赖、参数与候选固定顺序 → 同输入逐位同输出。
- **为什么有 (b)**：手写目标包含"车手需求满足度（Dx 残差）+ 阻力/刮底/胎温/改动幅度"。
  没有它，模拟优化会把车手反馈当空气（实测：不加守门时它会把 delta 全部覆盖成
  纯物理最快的解）。兑换率 5.0 的标定：单参数整幅改动的 effort 代价 0.02 → 需 ≥100ms
  模拟收益；需求残差增加 0.01（缺口显著扩大）→ 需 ≥50ms 收益。

## 6. 降级契约（不破坏既有行为）

| 场景 | 行为 |
|------|------|
| `model_type="rule"` | 不跑模拟，`model_type="rule"`，`simulation.reason` 说明 |
| 模型文件缺失/损坏 | 同上（`available=False`，`reason` 给出原因） |
| 赛道不在 13 赛道覆盖范围 | 同上（中性降级，合成 id 的既有测试不受影响） |
| 无诊断输入（无症状且无遥测发现） | 同上（"没有要解决的问题就不改车"） |
| 模型可用 + 有诊断输入 + 赛道覆盖 | `model_type="nn"`，`nn_available=true`，报告带完整轨迹 |

## 7. 验收（用现有遥测验证优化性能）

`python scripts/verify_optimization_telemetry.py`（6 赛道 × 3 场景）：

- 模型与引擎集成：覆盖赛道、默认调教预测 ≈ 0（锚点自洽）、推理确定性
- **优化效果双列对照**：
  - `NN 判定` —— 优化所用模型自己的评价
  - `真值复核` —— **解析仿真器（训练标签真值源）独立评价**（防"模型自我套利"）
- 赛道签名：模型给出的最优翼角排序（monaco/hungaroring 前列，monza/spa 后列）

实测（2026-09-19）：NN 判定平均 **+367 ms**，真值复核平均 **+631 ms**（NN 保守，
真值增益更大 → 无自我套利），18/18 场景均有提升。报告：`docs/Optimization_Verification.md`。

## 8. 复算步骤

```bash
# ① 构建遥测锚定仿真数据集（需要 data/training/corner_dataset.jsonl）
python scripts/build_setup_sim_dataset.py --setups 1400
python scripts/build_setup_sim_dataset.py --calibrate-only   # 复核标定表与赛道签名

# ② 训练纯标准库 MLP（无 PyTorch）
python scripts/train_setup_sim_nn.py --epochs 250 --hidden 48,24 --lr 0.008

# ③ 端到端验收（遥测 + 真值复核）
python scripts/verify_optimization_telemetry.py

# ④ 本地服务实测
python -m setup_tuner.cli        # 或 uvicorn setup_tuner.app:create_app --factory
# POST /api/v1/suggest {"track_id":"suzuka","model_type":"hybrid"}
```
