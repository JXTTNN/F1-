# 2026 遥测重训与端到端 A/B（2026-11-25）

## 一句话结论

**模型精度提升了，端到端调教收益没有提升。** 新模型在同类留出上把弯时占比 MAE 从
0.007306 降到 0.002836（−61%），覆盖从 19 站扩到 21 站；但在 42 组「模拟遥测 → 建议 →
独立物理仿真」的对照里，收益均值反而差了 5.5 ms（8 胜 / 7 负 / 27 平），
且 las_vegas 干地从 −105.9 ms 回退到 +5.9 ms。

**因此本轮不替换生产模型**，新权重作为 candidate 入库，供下一轮定位。

---

## 1. 数据：两个平台，全量干净圈

| 来源 | 内容 | 规模 | 用途 |
|---|---|---|---|
| 官方计时（FastF1，仓库 CI 产出） | Race 全量干净圈 + 逐弯样本 | **19,459 圈 / 314,891 条逐弯 / 21 站** | 主训练集 |
| OpenF1（`api.openf1.org`，第二平台） | 圈级 sector、速度陷阱、stint、进站 | **24,615 圈 / 1,324 stint / 863 次进站 / 21 站** | 交叉核对、轮胎/停站上下文 |
| f1laps 调教语料（游戏口径） | 20 项调教 + 圈速 | 899 条 / 24 站 | 独立任务，不与真实圈速配对 |

采集边界，必须说清楚：

- **EA F1 26 游戏内 UDP 遥测无法从网络爬取**，只能在游戏运行时由采集器抓本机 UDP。
  仓库里的 899 条调教是游戏口径，这就是"带调教"能拿到的全部公开数据。
- OpenF1 25 场 Race 中 lusail / yas_marina 的 `laps` 端点返回 404（远端缺数据），
  其余 21 站齐全；kuala_lumpur 是远端脏场次，已剔除。
- 原始逐点全量（约 1.2 GB 压缩）不在仓库内，本轮沿用仓库已入库的干净派生物。

数据卫生（对齐 `TRAINING_PLAN_2026-11-25.md`）：`max_*_g` 实为原始加速度 → ÷9.81 并
截尾 6 g；`max_long_g == 0` 视为缺失；`tyre_life` 字符串 `"None"` 转缺失；`drs_pct`
恒为 0 直接丢弃。逐弯样本 join 圈级表后，314,891 行全部拿到 stint 上下文。

## 2. 训练：先基准，再残差

新脚本 `scripts/train_telemetry_v3.py`：

1. **基准**：`(赛道, 弯号)` 弯时占比中位数，按经验贝叶斯向同弯型均值收缩（k=20）；
2. **残差**：14 个工况特征（弯型 / 胎 / 天气 / 温度 / 赛道需求画像）上做岭回归（α=3）；
3. **预测** = 基准 + 残差；产物仍是 `f1opt-telemetry-surrogate/1`，新增
   `corner_baseline` 块，引擎侧 `surrogate.py` 读到就走新路径，读不到维持旧行为。

### 2.1 同类留出（随机 20%，同一批测试行）

| 模型 | MAE（占比） | R² | 折算弯时误差 |
|---|---|---|---|
| 现役产物（19 站 one-hot 岭回归） | 0.007306 | 0.8511 | ±0.647 s |
| **新版（基准 + 残差）** | **0.002836** | **0.9739** | **±0.255 s** |
| 新版 + 轮胎上下文（离线实验） | 0.002836 | 0.9739 | ±0.255 s |

- MAE 降 **61.2%**；
- **轮胎上下文零增益**：加入 tyre_life / fresh / stint 后指标完全不动，与
  `TRAINING_PLAN` 的 ANOVA 结论一致（扣掉逐弯基准后，胎种只解释 2.5% 残差方差）；
- 现役产物的 `val_mae=0.0056 / R²=0.8993` 是它自己训练时的随机留出，与本表口径不同，
  不能直接对比，本表是把它放到新数据同一批测试行上重算的。

### 2.2 分站留出（15 训练 / 6 留出，`splits.json`）

| 模型 | MAE | R² |
|---|---|---|
| 现役产物 | 0.003028 | +0.9766 |
| 新版（基准 + 残差） | 0.025350 | +0.0275 |

**现役产物这一行是泄漏成绩**：它的 19 站覆盖里包含 madrid / spa / suzuka /
melbourne / monza / singapore 全部 6 个"留出站"，one-hot 里有这些弯的系数，
所以不是泛化。新版按分站留出评估掉到 R²≈0.03，与 `TRAINING_PLAN` 的
「跨赛道不可迁移」结论一致，是**已知边界，不是本轮退步**。

### 2.3 覆盖

19 站 → **21 站**（新增 `las_vegas`、`sao_paulo`），344 个弯对全部有基准。
共有 19 站里，逐弯重要度的平均 L1 变化只有 **0.004**（最大 0.014）——这解释了
下一节为什么大部分赛道结果一模一样。

## 3. 端到端 A/B：模拟遥测 → 建议 → 独立物理仿真

方法：21 站 ×（干/湿）= 42 组，输入同一份**模拟遥测摘要**（路肩冲击 2.2/1.7、
刮底 1.3、四轮温度/胎压/磨损、刹车温度、软胎），默认调教出发，走
`generate_suggestion(model_type="hybrid")` 真实调用路径；建议后的调教用
`simulate_lap_delta_ms`（遥测锚定准静态物理仿真，独立于代理模型）打分。

| 指标 | 现役模型 | 新版 |
|---|---|---|
| 运行成功 | 42/42 | 42/42 |
| 真正用上学出的重要度 | 38/42 | **42/42** |
| 平均物理收益 | −140.6 ms | −135.1 ms |
| 中位物理收益 | −106.8 ms | **−113.0 ms** |
| 平均改动条数 | 9.1 | 9.1 |
| 平均耗时 | 104.1 ms | 104.9 ms |

成对比较：**8 胜 / 7 负 / 27 平**。逐站差异：

- 变好：shanghai 干 −33.5 ms、monaco 湿 −57.9 ms、madrid 湿 −29.5 ms、sao_paulo 干 −5.6 ms
- 变差：las_vegas 干 **+111.8 ms（−105.9 → +5.9，比默认调教还慢）**、
  hungaroring 干 +37.0 ms、melbourne 湿 +83.7 ms、zandvoort 湿 +41.5 ms

还有一个**与本次训练无关的既存问题**：spielberg（干 +144.5 ms / 湿 +524.9 ms）与
spa 干（+41.8 ms）在两版模型下都给出"比默认更慢"的建议，说明这几站的
物理锚点或优化目标本身有偏差，应单独开 issue 查，不要算到模型头上。

---

## 4. 为什么精度提升没有变成收益

1. **重要度几乎没变**：19 个共有站的平均 L1 只差 0.004，优化器拿到的权重几乎一样，
   27/42 组输出完全相同。
2. **优化器对权重是离散敏感的**：剩下 15 组里，权重动一点点就会翻越某个台阶，
   结果在 ±100 ms 级别跳动（las_vegas 就是典型），说明当前最优点附近的平台很窄。
3. **瓶颈不在代理模型**：调教收益主要由物理仿真/优化器的目标函数决定，代理模型只
   提供逐弯权重。把 MAE 从 0.007 降到 0.003，在权重层面的信号强度不足以穿透这个瓶颈。

这也意味着：继续在"逐弯弯时占比"上加特征（轮胎、天气）不会带来端到端收益，
该改的是优化目标与锚点质量。

---

## 5. 本轮决策

- **生产模型不变**：`setup_tuner/resources/models/telemetry_surrogate.json` 保持原样。
- 新权重入库为 **candidate**：
  `setup_tuner/resources/models/candidates/telemetry_surrogate_v3.json`。
- 引擎保留 baseline 能力（`surrogate.py` 新增 `corner_baseline` 读取），
  旧产物无该块时行为完全不变（333 条相关测试通过）。
- 新增脚本：`scripts/train_telemetry_v3.py`、`scripts/crawl_openf1.py`、`scripts/e2e_ab.py`。

## 6. 复现

```bash
# 1. 采集第二平台（可选，仓库已带 manifest）
python scripts/crawl_openf1.py

# 2. 把干净训练集解压成训练脚本认识的路径
gzip -dc data/f1_2026/train/corner_samples_clean.jsonl.gz > data/training/corner_dataset.jsonl

# 3. 训练 + 对照实验（--experiment-only 只出报告不写模型）
python scripts/train_telemetry_v3.py --experiment-only

# 4. 端到端 A/B（需要旧产物与新产物各一份）
python scripts/e2e_ab.py --old <旧模型.json> --new <新模型.json>
```
