## 二、采集结果

- robots.txt 明确 `Allow: /` 且 `Content-Signal: ai-train=yes`；只抓公开页面，不碰 `/api/`。
- 本次抓取 **708 条**（21 站，Time Trial 420 / Race 288），全部干地；每站中位 36 条。
- 与仓库已有 899 条合并后，训练样本 **1,319 条 / 25 站**。

> 注：f1laps 的分页由前端 JS 控制，列表页每站只暴露约 21–39 个链接；
> 要拿到全站数千条需要浏览器自动化，本轮先用可得规模，管线已可增量重跑。

## 三、排序模型

| 指标 | 值 |
|---|---|
| 赛道内 5 折 Spearman（中位） | **0.497** |
| 最好的站 | hungaroring 0.731、barcelona 0.558、austin 0.530 |
| 最差 | imola −0.570（n=20，样本太少） |
| 全局岭回归（含赛道哑变量） | 0.390 |

分位定义：同站干地内按圈速排名，**0 = 最快**。分位化消掉了赛道长度、车与驾驶水平
的绝对值差异，只保留"这套调教在该站的位置"。

## 四、融入系统

`sim_optimizer.meta_align()` 在边界夹紧之后运行：

1. 用 ranker 算当前建议的分位；≤0.55 不动（已经在快调教区间里）；
2. 否则按 `PULL_RATIO=0.55` 朝该站前 25% 的中位数拉，**每参数最多一档 `max_delta`**
   （产品契约：单参数改动不得超过 max_delta，多处测试守着）；
3. 分位至少改善 0.01、且引擎模型损失不超过 250 ms 才采纳；
4. 湿地直接跳过（干地 meta 不能评湿地建议，产品契约：雨天调整幅度不得大于干地）。

左/右胎压强制同步，边界与档位按游戏设定对齐。

## 五、检验

### 5.1 逐站分位（21 站，干地，默认调教起步）

| 轮次 | 平均分位 |
|---|---|
| 0（默认） | 0.663 |
| 1 | 0.660 |
| 2 | 0.625 |
| 3 | 0.554 |
| **4** | **0.493** |

四轮采纳后从"比中位慢"进入该站前 50%（0.663 → 0.493）。
**物理代理 +159 ms（比默认慢）**——这是必须说清楚的代价：物理模型的翼角/前悬挂
灵敏度正是被压平的那两项（见 `AERO_V2_2026-11-26.md`），而语料显示该站快调教就是
高翼角 + 硬前悬。这里选择以**游戏语料**为准，物理只做 250 ms 的护栏。

上线后需要在游戏里实测验证：如果真实圈速没有跟着分位改善，说明语料先验不成立，
应回退 `_META_PULL=False`。

### 5.2 单轮口径（42 组，默认起步）

| 指标 | 关闭 meta 对齐 | 开启 |
|---|---|---|
| 平均分位 | 0.630 | **0.531** |
| 物理代理 | −749 ms | −351 ms |

（单轮口径下 meta 会把已到位的诊断方向按剩余档位微调；最终版只动"诊断没碰过"的参数，
以保证风格差异不被抹平。）

差异来自"物理代理 vs 游戏语料"的分歧：物理模型的翼角敏感度被压平（见
`AERO_V2_2026-11-26.md`），而语料显示该站快调教就是 50/50。这里选择**以游戏语料为准**，
物理只做护栏。这条取舍必须写进报告，不能只报好看的那个数。

### 5.3 回归

- `pytest -q`：**2251 passed / 5 skipped**
- 期间修掉三个契约冲突：单参数超 `max_delta`、左右胎压不同步、湿地调整幅度超过干地。
