## 1. 安装与启动

### 方式一：便携包（Windows，推荐给车手）

1. 到 [Releases](https://github.com/JXTTNN/F1-/releases/latest) 下载 `F1OPT-portable.zip`
2. 解压到任意目录（不要放系统目录）
3. 双击「一键启动.bat」→ 浏览器自动打开 `http://127.0.0.1:8000`

无需安装 Python，模型与 24 条赛道数据都在包内。

### 方式二：pip / 源码

```bash
pip install "git+https://github.com/JXTTNN/F1-"
f1opt
```

或者：

```bash
git clone https://github.com/JXTTNN/F1-.git
cd F1-
pip install -e ".[dev]"
python -m setup_tuner.cli
```

### 命令行参数（当前只支持这些）

| 参数 | 作用 |
|---|---|
| `--host HOST` | API 监听地址（默认 `127.0.0.1`） |
| `--port PORT` | 面板端口（默认 `8000`） |
| `--no-browser` | 启动后不自动开浏览器 |
| `--keep-telemetry` | 退出时保留派生遥测数据（等价 `F1OPT_KEEP_TELEMETRY=1`） |
| `--version` | 打印版本 |

### 游戏内设置（接遥测）

F1 2026 → Settings → Telemetry：

| 项 | 值 |
|---|---|
| UDP Telemetry | `On` |
| UDP Format | `2026` |
| UDP Port | `20777` |
| UDP IP | `127.0.0.1` |

## 2. 面板功能

面板是单页应用（`http://127.0.0.1:8000`），从上到下六个区块：

### 2.1 赛道图

- 左上角下拉框选赛道（24 站），或由 Session 包自动识别。
- 图上每个弯是一个**可点击热区**（T1、T2…）；点弯即打开反馈面板。
- 当前弯的弯型（慢 / 中 / 快）会显示在实时遥测区。

### 2.2 实时遥测

- 转速、速度、档位、当前圈时、扇区、当前弯。
- 顶部状态点：`已连接` / `等待遥测`；显示抓包地址（`0.0.0.0:20777`）。
- 按钮：`开始监听 / 停止监听`、`录制`、`录制库`、`导出训练样本`。
- 没有游戏时可点「模拟遥测」让整条链路跑起来（用于验证安装）。

### 2.3 调教参数输入

- 20 项参数，按 6 大类分页（空动 / 变速箱 / 悬挂几何 / 悬挂 / 刹车 / 轮胎）。
- **导入当前调教**：从游戏车库的 Car Setups 包（Packet 5）一键读取；没连遥测时返回 409。
- **保存调教**：把当前输入存为该赛道快照；**恢复默认**回到默认值。

### 2.4 弯道反馈

- 点弯 → 弹出「多症状录入」，21 个症状按入弯 / 弯中 / 出弯 / 全局分组，
  只显示当前弯阶段可用的项。
- 每个症状可勾选 + 选强度（1 轻微 / 2 明显 / 3 严重），一次可勾多个。
- 提交后写入反馈摘要；`清空反馈` 可整批删除。

### 2.5 调教建议报告

点「生成建议」后输出：

| 区块 | 内容 |
|---|---|
| 摘要 | 关联参数数、非零调整数、赛道画像 |
| 逐参数表 | 当前值 / 调整量 / 建议值 / 联动依据 / 取舍说明 |
| 整体性调教 | 逐弯加权依据、跨弯冲突折中、整体收口、改动轨迹 |
| 神经网络模拟 | 模型描述、迭代轮次、采纳次数、记账收益、逐步采纳轨迹；该站有真实校准数据时同一行显示「真实校准 **NN% 准**」——`NN` 是 `holistic.simulation.real_calibration.accuracy`（该站留出集的同队同会话配对排序正确率），悬停可看到融合权重 `weight`。徽标刻意显示**准确率而不是权重**：`weight: 0.9` 说的是「9 成听真实数据」，不是「9 成准」 |
| 风格定向 | 按驾驶特征微调了哪几项、圈速代价、未采纳项及原因 |
| 置信度 | high / medium / low |

模型选择在报告区右上角：`rule`（纯规则）/ `nn` 或 `hybrid`（规则方向 + 神经网络模拟精修）。

### 2.6 迭代历史

每次生成建议都会记一条，可回看当时的报告与参数变化。

### 2.7 录制与回放

- 「录制」把原始 UDP 字节写成 `.f1rec`（**永久保留**，不随退出删除）。
- 「录制库」可查看会话、按倍速回放（回放走真实解析链路）、停止回放。
- 「导出训练样本」把录制整理成逐圈训练样本（`data/training/`）。

## 3. 标准使用流程

| # | 操作 | 应该看到 |
|---|---|---|
| 1 | 启动 `f1opt`（或双击一键启动） | 浏览器打开面板，状态点显示「等待遥测」 |
| 2 | 选赛道（或进游戏让遥测自动识别） | 赛道图与弯数正确（如 suzuka 18 弯） |
| 3 | 导入当前调教（可选） | 参数面板填入游戏里的 20 项数值 |
| 4 | 跑一圈（至少 3 圈风格才启用） | 实时遥测跳动；圈速/扇区有数 |
| 5 | 点问题弯录反馈，或什么都不点 | 反馈摘要出现条目；纯遥测也能自动发现问题 |
| 6 | 点「生成建议」 | 报告表 20 行、模拟轨迹、风格定向段 |
| 7 | 照着改，再跑一圈对比 | 迭代历史多一条；下一轮反馈从空开始 |

> 反馈是**每圈一次**的消耗品：生成建议后本赛道反馈会被清空
> （可用 `clear_feedback_after_suggest: false` 保留）。设计目的是避免
> 上一圈的问题和这一圈混在一起。

## 4. 车手风格（12 维）

### 4.1 采集

- 每跑完一圈，`StyleExtractor` 把整圈遥测压成 11 维（攻弯强度 / 转向平滑度 /
  油门 / 刹车 / 循迹刹车 / 给油时机 / 轮胎管理 / 滑移 / 直道末速 / 制动热负荷 /
  慢弯占比），第 12 维「圈速一致性」由历史圈时方差补齐。
- 落库按 EMA 混合；**样本 ≥3 圈**才启用，之前面板显示「风格采集中 (n/3)」。

### 4.2 生效方式（两层）

| 层 | 做什么 | 约束 |
|---|---|---|
| 幅度调制 `gain_for_style` | 按风格缩放参数调整幅度 | 受 `max_delta` 与档位对齐约束 |
| 定向动作 `style_trims` | 给 ±1 档偏好动作（前翼 / 防倾杆+悬挂 / 刹车压力 / 差速器 / 四轮胎压） | 每条过性能模型算圈速代价；单条 ±30ms 可信区间、整层 25ms 预算 |

被拒绝的动作不会静默丢弃，报告里写明「代价多少 / 超预算 / 与已采纳动作组合后越界」。

### 4.3 怎么读报告

- 顶部徽标「已应用风格调制（N 圈样本）」= 风格向量已参与生成。
- 报告「风格定向」段：
  - `按你的驾驶特征微调 2 项：… 预测圈速代价 -2.9 ms（预算 25 ms）`
  - `另有 2 项风格偏好未采纳：…（预测代价 +41ms 超出可信区间）`

## 5. REST API

基址：`http://127.0.0.1:8000/api/v1`。
所有响应统一信封：`{"code": 0, "message": "...", "data": ...}`（`code != 0` 即失败）。

### 5.1 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 + 遥测连接状态 |
| GET | `/tracks` | 24 条赛道清单 |
| GET | `/tracks/{track_id}` | 单站详情（弯数、长度等） |
| POST | `/tracks/current` | 选当前赛道，body `{"track_id": "suzuka"}` |
| POST | `/setup/import` | 从 Packet 5 缓存导入当前调教（无遥测 → 409） |
| GET | `/setup/current?track_id=` | 读取该赛道最新调教快照（无 → 404） |
| GET | `/setup/fields` | 20 项参数定义（min/max/step/default） |
| POST | `/setup/manual` | 手动保存调教，body `{"track_id", "params": {20 项}}` |
| POST | `/feedback` | 提交反馈（单条或 `feedbacks` 批量） |
| GET | `/feedback?track_id=` | 查询反馈 |
| POST | `/suggest` | 生成建议，body `{"track_id", "model_type": "nn"}` |
| GET | `/suggest/latest?track_id=` | 最近一次建议报告 |
| GET | `/driver/style?track_id=` | 12 维风格向量 + 是否启用 |
| GET | `/iteration/history?track_id=` | 迭代历史 |
| POST | `/telemetry/simulate` | 模拟遥测，body `{"track_id", "action": "start\|stop"}` |
| POST | `/telemetry/listener/toggle` | 监听开关，body `{"action": "start\|stop"}` |
| POST | `/telemetry/record/toggle` | 录制开关，body `{"action": "start\|stop"}` |
| GET | `/telemetry/recordings` | 录制会话列表 |
| GET | `/telemetry/recordings/{session_id}` | 录制详情 |
| POST | `/telemetry/recordings/{session_id}/export` | 导出逐圈训练样本 |
| POST | `/telemetry/replay/start` | 回放，body `{"session_id", "speed"}` |
| POST | `/telemetry/replay/stop` | 停止回放 |
| GET | `/telemetry/replay/status` | 回放状态 |
| POST | `/telemetry/import-file` | 导入 JSON 遥测（文件或目录），body `{"path"}` |
| POST | `/telemetry/experiment` | 两套调教 A/B 对比 |
| WS | `/api/v1/ws` | 实时推送（遥测帧、建议、状态） |

### 5.2 示例

```bash
BASE=http://127.0.0.1:8000/api/v1

curl -s $BASE/health
curl -s $BASE/tracks
curl -s -X POST $BASE/tracks/current \
  -H 'Content-Type: application/json' -d '{"track_id":"suzuka"}'

# 提交反馈（弯道级）
curl -s -X POST $BASE/feedback -H 'Content-Type: application/json' \
  -d '{"track_id":"suzuka","corner_number":1,"symptom":"understeer","strength":2}'

# 生成建议（nn = 规则方向 + 神经网络模拟精修）
curl -s -X POST $BASE/suggest -H 'Content-Type: application/json' \
  -d '{"track_id":"suzuka","model_type":"nn"}'

# 风格画像
curl -s "$BASE/driver/style?track_id=suzuka"
```

`suggest` 的 `data.report` 关键字段：

| 字段 | 含义 |
|---|---|
| `setup_delta` | 20 项调整量（已档位对齐） |
| `model_type` | 实际使用路径（`rule` / `nn`） |
| `holistic.simulation` | 迭代轮次、采纳次数、`gain_ms`（记账）/`raw_gain_ms`（原始预测） |
| `holistic.style_targeting` | `enabled` / `applied` / `rejected` / `cost_ms` / `budget_ms` |

## 6. 配置与数据位置

环境变量（`F1OPT_` 前缀，或项目根目录 `.env`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `F1OPT_API_HOST` | `127.0.0.1` | 面板 / API 监听地址 |
| `F1OPT_API_PORT` | `8000` | 面板端口 |
| `F1OPT_UDP_HOST` | `0.0.0.0` | 遥测监听地址（收广播需绑所有网卡） |
| `F1OPT_UDP_PORT` | `20777` | 遥测端口 |
| `F1OPT_DATA_DIR` | `<安装根>/data` | 数据目录 |
| `F1OPT_KEEP_TELEMETRY` | 未设置 | `1` = 退出时保留派生遥测 |
| `F1OPT_LOG_LEVEL` | `INFO` | 日志级别 |

数据位置（都在安装根目录内，不写用户主目录）：

| 数据 | 位置 | 退出时 |
|---|---|---|
| 录制 `.f1rec` + 逐圈样本 | `data/recordings/` | **永久保留** |
| 反馈 / 建议 / 迭代 / 调教快照 | `data/f1opt.db` | 保留 |
| 派生遥测（训练集 / 模拟包流） | `data/training/`、`data/sim_telemetry/` | **自动删除** |
| 模型 | `setup_tuner/resources/models/` | 随包分发 |

## 7. 常见问题

**Q：一直显示「等待遥测」？**
检查游戏 UDP 是否 `On`、格式是否 `2026`、端口是否 `20777`；面板地址应显示
`0.0.0.0:20777`。防火墙第一次启动要允许 Python / F1OPT.exe。

**Q：点「导入当前调教」返回 409？**
说明还没收到 Car Setups 包（Packet 5）。先进游戏车库 / 调教界面停一下，
或先用「手动设置」保存一份。

**Q：风格一直显示「采集中 (1/3)」？**
每圈都要跑完整（帧数达标才落库）。v1.6.14 及更早版本有一个落库 Bug：
第 2 圈起风格样本写入失败，样本永远停在 1 —— 升级到 **v1.6.15** 即可。

**Q：报告里没有「风格定向」段？**
三种情况会在该段写明原因：样本 <3 圈、模型不可用、风格特征不显著
（12 维都接近中性，没有可执行偏好）。不是静默丢弃。

**Q：建议改得太多 / 太少？**
- 太多：模型有单步 80ms、累计 120ms、最多 3 步的记账上限；
  到上限会在模拟段说明「跑一圈再生成一次」。
- 太少：诊断没发现的问题不会改车（无输入不改车是硬契约）。

**Q：EXE / 便携包被杀毒软件拦截？**
Nuitka onefile 自解压容易被误判，添加信任或改用 pip 安装。

**Q：反馈提交后怎么没了？**
生成建议时默认清空本赛道反馈（已消费）。要保留可在请求里带
`"clear_feedback_after_suggest": false`。

**Q：赛道 ID 在哪看？**
`GET /api/v1/tracks`。当前 24 站：
`melbourne, shanghai, suzuka, sakhir, jeddah, miami, montreal, monaco,
barcelona, spielberg, silverstone, spa, hungaroring, zandvoort, monza,
madrid, baku, singapore, austin, mexico_city, sao_paulo, las_vegas,
lusail, yas_marina`。

## 8. 开发者自检

```bash
pytest -q                                  # 全量测试（2183 项）
ruff check setup_tuner tests scripts
node --check setup_tuner/ui/app.js

python scripts/audit_full_flow.py          # 全流程审计（31 项断言）
python scripts/eval_usage_flow.py          # 使用流程门禁（24 赛道 × 5 场景）
python scripts/eval_style_targeting.py     # 风格定向门禁
python scripts/api_endpoint_test.py        # REST 契约
python scripts/perf_benchmark.py           # 性能基准
python scripts/ui_audit.py                 # 真人式 UI 点击（需先起服务）
```

UI 审计需要先起一个隔离实例：

```bash
F1OPT_DATA_DIR=.ui_audit_data python -m uvicorn setup_tuner.app:create_app \
  --factory --host 127.0.0.1 --port 8199
AUDIT_BASE=http://127.0.0.1:8199 python scripts/ui_audit.py
```
